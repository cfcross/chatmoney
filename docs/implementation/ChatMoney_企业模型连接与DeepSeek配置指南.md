# 个人模型连接与 DeepSeek 配置指南

## 吴姐和组员分别怎么设置

**ChatMoney 账号和密码**用于登录所属企业的工作台。**DeepSeek API Key** 是模型服务的调用密钥，费用记在对应的 DeepSeek 账户。登录成功后才会看到填写模型密钥的地方。

1. 在 DeepSeek 官方平台登录你本人用于付费的 DeepSeek 账户，在密钥管理页创建一把专用 API Key，并存入自己的密码管理器。确认账户有可用余额。[官方密钥管理](https://platform.deepseek.com/api_keys) · [官方入门](https://api-docs.deepseek.com/)
2. 打开 ChatMoney 加密工作台，用你自己的管理员或成员账号登录。第一次使用本机证书的步骤见下节。
3. 进入“助手管理 → 创建助手”。填写基本信息后，在“角色设置 → 使用的模型”选择 DeepSeek。点“添加 DeepSeek 连接”，填名称，例如“我的主连接”，再填 API Key。
4. 点“保存并测试连接”。后台先加密保存，再查询账户可用状态和可用模型。页面只在你点测试时发起这些查询。测试过程不发送聊天，也不会产生聊天生成的用量。[账户状态](https://api-docs.deepseek.com/api/get-user-balance/) · [可用模型](https://api-docs.deepseek.com/api/list-models/)
5. 显示“连接可用”后，选择模型。默认推荐 Flash。需要时，可选择同一连接下的 Pro。下拉列表取官方返回结果与引擎支持型号的交集。核对日期为 2026-11-14。[官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)
6. 选择已发布的知识资料，填可回答范围，核对转人工条件，再发布助手。到助手详情查看当前发布版的模型。新建客服或第二位销售助手时，直接选择“我的主连接”。

每个 ChatMoney 账号管理自己的连接，管理员也只能管理自己的密钥。要分开结算，请各自使用独立 DeepSeek 账户签发的密钥。同一个 DeepSeek 账户签发的多把密钥仍由该账户结算。

实际运行时，助手会发出模型请求。一次来信可能先做需求分析，再生成答复，还可能在工具返回后继续调用。模型收到的是这次对话所需的已批准资料和客户上下文。请先用模拟资料试运行。消息渠道仍是模拟渠道。

## 本机启动、登录、停止

在项目已有的 Windows 开发环境中运行以下 PowerShell 命令。首次使用 `-TrustCertificate` 会登记本项目的本地证书，仅影响当前 Windows 用户。平时启动省略此开关。若管理员已部署受信任的 HTTPS 服务，则使用管理员提供的地址。

```powershell
# 在项目根目录执行
& .\scripts\model-workbench.ps1 start -TrustCertificate
& .\scripts\model-workbench.ps1 status
```

启动器应用待执行的迁移，启动本机服务，并在项目的 `.runtime/account-setup/` 目录准备首次设置管理员密码的专属网页。打开本企业的 HTML 文件，在浏览器设置密码。已设置密码的管理员可以直接登录。成员由管理员在工作台开通。[账号开通步骤](ChatMoney_Agent中文管理界面使用指南.md)

- 日常登录和管理模型连接使用 HTTPS 工作台。旧的 HTTP 工作台入口提供前往加密登录页的链接。
- 若浏览器报告证书不受信任，先核对地址为本机，再运行上述首次信任命令。开发脚本创建的证书有效期为一年。证书更新时保留受保护的主密钥。
- 切换自正在运行的 V1.0 启动方式时，先运行 `& .\.runtime\live.ps1 stop`，再执行 V1.1 启动命令。以后统一用新脚本管理服务。
- 停止工作台与 Worker 用 `& .\scripts\model-workbench.ps1 stop`。如还要关闭本机数据库，执行 `& .\.runtime\postgres\bin\pg_ctl.exe -D .runtime/pgdata -m fast -w stop`。

## 日常维护和排错

在“助手管理 → 我的模型连接”选择你自己的连接。保存后页面只显示名称、最近测试时间、状态和可用型号。密钥输入框在提交后会清空。

| 看见的情况 | 下一步 |
|---|---|
| 等待测试 | 已加密保存。点“重新测试”，待显示“连接可用” |
| 密钥无效或权限不足 | 核对 你自己的 DeepSeek 账户，点“更换密钥”，输入新值并测试 |
| 余额不足 | 在官方账户检查余额，处理后重新测试 |
| 超时、限流、服务异常 | 查看执行记录。稍后重试一次，避免反复创建同一任务 |
| 当前模型不可用 | 重新测试连接。在助手草稿选择可用型号，发布新版本供新任务使用 |
| 服务端加密配置缺失或无法解密 | 维护者检查 API 和 Worker 的主密钥及所属 Windows 账户，恢复原配置 |
| 已停用 | 查看引用助手，必要时为它们选另一条已验证连接并发布新版本 |
| 草稿或历史版本仍在引用 | “查看引用助手”会列出名称与版本。删除会被阻止，仍可二次确认停用 |

**更换密钥**保留连接编号。通过测试后，所有绑定它的助手下次调用就使用新凭证。新密钥测试失败期间暂停使用。已经发给供应商的请求可能已计费。**切回模拟**请在角色设置选“模拟模型”并发布。旧任务固定使用原版本，需要停下旧任务并用新版本建任务。若须立即阻止后续真实模型请求，可先停用连接，留意同一连接下的其他助手。

**控制用量。** 演示和回归测试选模拟模型，真实试用先选 Flash。工作台“客户会话与任务 → 执行记录”可查模型调用次数；开发者查询该次执行可见供应商返回的输入和输出用量。余额和账单以 DeepSeek 平台为准。引擎限制每轮调用次数、重试次数和输出长度，本版未实现企业金额预算或扣费上限。[官方计费说明](https://api-docs.deepseek.com/quick_start/pricing/)

## 维护者的加密配置

- 连接使用 AES-256-GCM 认证加密，每次保存生成新随机数。新建和更换后的密文与企业、账号和连接编号一起校验。主密钥是 32 个随机字节的 URL 安全 Base64 表示。数据库存储连接密文，助手版本仅保存连接编号、模型名称、可选参数。
- 本机启动器首次运行自动生成主密钥。Windows 的 DPAPI（当前用户数据保护）加密保存于当前账户的本地应用数据目录，位于工程之外。HTTPS API 和 Worker 使用同一份受保护配置。主密钥始终留在服务器，模型密钥仅在提交、验证或调用时短暂出现在相应进程内存中。
- 若已有部署密钥，通过服务管理器给 API 和 Worker 注入相同的 `CHATMONEY_CREDENTIAL_ENCRYPTION_KEY`。使用私有密钥管理器备份原值。其他机器或其他 Windows 账户需要恢复同一主密钥或重新录入个人密钥。轮换 DeepSeek 密钥使用页面“更换密钥”；更换服务器主密钥需要另行安排已有连接的重加密。
- 无主密钥时仍可运行模拟模型，服务拒绝保存个人密钥。Windows 启动器仅为当前项目绑定本机地址。Compose 已传递主密钥变量，容器部署需另行配置受信任的 HTTPS 直连或 TLS 透传。接收密钥的接口不接受通过 `X-Forwarded-Proto` 声明的 HTTPS。部署时关闭保存请求体、认证头或完整查询字符串的日志。
- 新助手默认使用模拟模型。已保存的连接保留给原始创建账号。付费助手要求连接和助手属于同一账号，后台每次发出模型请求时都会核对。旧助手引用过别人的连接时，由助手创建者重新绑定个人连接、发布并按新版本创建任务。旧任务缺少本次调用的个人授权记录时，请本人重新发起。

## 开发者入口

原 29 个业务操作使用原路径。连接管理有独立的 API 文档及登录校验。写操作要求工作区身份、HTTPS、请求体和 `Idempotency-Key`（同一次提交的去重编号）。修改已有连接还需提交上次读取的 `expected_revision`（修订号）。接口从登录凭证确定企业和账号。原业务接口 · 个人模型接口

| 前缀 `/api/model-admin/v1` 下的操作 | 用途 |
|---|---|
| `POST /connections` | 保存连接名称及加密后的密钥，返回“等待测试” |
| `GET /connections` | 查询登录账号自己的连接和最新状态 |
| `GET /options` | 读取登录账号已验证的个人连接 |
| `POST /connections/{id}/test` | 主动验证，并保存成功或失败的结果 |
| `PATCH /connections/{id}` | 修改名称或轮换密钥。轮换后要再测试 |
| `GET /connections/{id}/usage` | 查看引用此连接的草稿与历史发布版本 |
| `POST /connections/{id}/disable` | 停用连接。有引用时要求显式确认 |
| `DELETE /connections/{id}` | 删除零引用连接 |

连接测试返回 HTTP 200 代表测试操作已完成。请读取返回的 `status` 和 `last_error_code` 判定连接可用性。常见失败为缺权限 403、其他账号的连接不可见 404、引用中或版本冲突 409、字段无效 422、加密配置缺失 503。
