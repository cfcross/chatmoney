# Intelligent_Marketing

Healing-Fun 的自动化营销 agent 平台。

平台由一套共享引擎和两条业务线组成：引擎接收客户来信，完成事实检索、政策判定、答复生成、渠道发送与回执确认，必要时转人工；ToB 业务线负责企业外联、报价与合同，ToC 业务线负责店铺客服、社群内容与直播。两条线跑同一个引擎，差异只体现在政策规则、资料与渠道接入方式上。

## 引擎能做什么

- **会话处理**：分析客户来信 → 取回记忆与知识 → 生成答复 → 政策校验 → 发送 → 确认回执；不适用的场景转人工。
- **角色与版本**：每个助手绑定产品、工具与规则；配置以版本发布，历史会话按当时的版本执行。
- **知识库**：资料库 → 文档 → 分块 → 快照；改内容走新快照，不改历史。
- **记忆**：结构化事实与摘要分开存放，每次变更带来源与操作者，可人工纠正。
- **管理后台**：运行总览、成员账号、助手管理、资料库、客户会话与任务、人工接管。
- **隔离与权限**：多租户，租户隔离在数据库层生效；写操作需要幂等键。

明确不做的：虚构人格、平台自动化滥发、未授权使用真人音色或形象。

## 快速开始

引擎跑起来需要 PostgreSQL 与 Python 3.12，且**迁移账号与运行账号必须是不同用户**。完整命令、环境变量与已知基线（当前 90 通过 / 1 失败）见 [`AGENTS.md` 第 4 节](AGENTS.md) —— 命令只在那里维护，避免两处漂移。

## 参与协作

1. 先读 [`docs/ROADMAP.md`](docs/ROADMAP.md) 了解阶段与当前缺口。
2. 再读 [`AGENTS.md`](AGENTS.md)：红线、命令、以及「哪些能自己改、哪些要先问」。
3. 引擎内核（`app/workflows.py`、`app/channels.py`、`app/policies.py` 等）由引擎维护者主责；接口与数据格式的变更先提 issue 再实施。
